## A2. Phase plan (data-driven, per form)
Each form ships a **phase plan**: an ordered list of phases with fixed durations, generated by the build from the audio manifest (Part B) and the level-config templates.

```ts
type Phase =
 | { kind:"instruction"; part:number; asset:string; ms:number }        // spoken + on-screen instruction
 | { kind:"preread"; part:number; ms:number; items:string[] }          // silent; items visible
 | { kind:"play"; part:number; segment:string; play_no:1|2; asset:string; ms:number }
 | { kind:"gap"; part:number; ms:number }                              // between plays / texts
 | { kind:"answer"; part:number; ms:number }                           // after the last play of a text/part
 | { kind:"review"; ms:number };                                       // OD-03
```

**Provisional B1 template [UNKNOWN / KLARWEG DESIGN DECISION]**, to be re-timed against the official full recording once obtained (Standard B3):

| Part | Sequence | Provisional values |
|---|---|---|
| T1 | instruction → example preread **10 s** [OFFICIAL] → example play **once** (no gap, no answer phase; owner decision H-2) → for each of 5 texts: label + item preread → play 1 → gap → play 2 → answer | item preread 10 s · gap 5 s · answer 10 s |
| T2 | instruction → preread **60 s** [OFFICIAL] → play 1 → answer | answer 15 s |
| T3 | instruction → preread **60 s** → play 1 → answer | answer 15 s |
| T4 | instruction → preread **60 s** → play 1 → gap → play 2 → answer | gap 10 s · answer 15 s |
| Review | answers editable, no audio | **5 min** (OD-03; mirrors paper transfer time [OFFICIAL]) |

**Instruction phases (implementation, owner decision H-1, 2026-10-10):**
- A part's spoken instruction is an optional audio asset named on the Hören part placement (`instruction_asset_id`,
  EXAM-ITEM-SCHEMA §4).
- The phase plan plays it once, as the part's first phase, with the asset's **measured** duration. It is a
  non-recoverable `play` phase (it never uses up the OD-05 recovery replay).
- It replaces the part's fixed `instruction_seconds` timer, which stays 0 in `lc:b1@1`. No OD-43 value changes.
- Parts without an instruction asset are planned exactly as before.
- Whether a form's total lies within gate Q5 (36–42 min) is decided by its measured audio (B7).

**Expected total** (with measured official-like durations, B6):
- audio ≈ 24–26 min (T1 ≈ 2 × 5 × 45 s, T2 ≈ 170 s, T3 ≈ 210 s, T4 ≈ 2 × 310 s)
- pre-read ≈ 4 min, instructions ≈ 2 min, gaps/answers ≈ 3 min
- plus a 5 min review

That totals **≈ 38–40 min**, consistent with the official "ca. 40 Minuten" [OFFICIAL]. Gate Q5 requires the total to fall within 36–42 min.

## A3. Preload and buffering
1. At Hören start, the client requests `POST /media {purpose:"hoeren_preload", part}` → signed URLs for that part's segments. It downloads them fully with `fetch()` and decodes them into memory (`AudioBuffer` via WebAudio).
2. The **pre-read timer for a part starts only after all of that part's audio is decoded** (the client sends `phase_ack: ready`). Waiting time ("Audio wird geladen…") is not exam time. If it isn't ready after 120 s → incident + retry/abort option.
3. Next-part preload runs in the background during the current part's playback. Memory budget ≤ 60 MB (Opus).
4. After a segment's final allowed play, its buffer is released (`AudioBuffer` dropped, blob URLs revoked).

## A4. Playback, play-count enforcement, pause and seek
- Playback uses **WebAudio** (`AudioBufferSourceNode`). There is **no `<audio controls>`**, so no native pause/seek/speed UI exists.
- **Pause:** none. **Seek:** none. **Speed:** fixed 1.0 [DESIGN; OS §23.1 mock disables slow controls]. Volume: a slider (master gain) only.
- **Start:** the first play of the module needs one user gesture ("Hören starten") to unlock the audio context (autoplay policy). After that, playback is automatic per the phase plan.
- **Play counts:** enforced in three layers:
  1. The engine's phase plan.
  2. Server phase acks: `play_start` / `play_end` with server timestamps. The server rejects a `play_start` beyond the allowed count, or one out of plan order.
  3. Audit: `audio_plays` rows; anomalies (e.g. a play_end before the duration has elapsed) → incident flag.
- **Residual risk [DESIGN]:** a technically skilled user could replay decoded audio via developer tools. Klarweg is a learning product, so the risk is accepted, monitored and reduced by releasing buffers and only ever having decoded data in memory. Optional hardening later (segment-wise decrypt keys per play).

## A5. Questions and reading windows
- During `preread`, the part's items are visible and answerable.
- During `play`/`gap`/`answer`, items stay visible and answerable.
- Items of **future parts are not shown** until their instruction phase.
- Items of **finished parts remain editable** until the module ends (consistent with the official "changes allowed until submission" [OFFICIAL]; navigation-back UI behaviour is **[UNKNOWN / KLARWEG DESIGN DECISION, OD-02]**).
- H1: the two items of a text are shown together. H4: a grid with speaker names as columns (moderator included).

## A6. Section timing
- The server computes `planned_start/end` for every phase from the `ready` ack.
- The module deadline is the sum of all phases + ≤ 60 s total jitter allowance.
- The client never extends phases. Drift > 2 s between client and server phase → resync to the server plan (the client skips ahead silently in gaps; never truncates a play mid-text unless the module deadline is reached).

## A7. Interruption recovery [UNKNOWN / KLARWEG DESIGN DECISION, OD-05]
| Event | Behaviour |
|---|---|
| Tab hidden / app switched | Playback continues (WebAudio keeps running on desktop). On iOS, a suspended context is detected via `statechange` → treated as an interruption |
| Device sleep / audio context suspended mid-play | Mark the play `interrupted`. On return: **one recovery play of that segment from its start** per module (logged), only if the interrupted play was the *last* allowed play of the segment; otherwise continue with the next allowed play |
| Network loss | No effect on playback (preloaded). Answers queue locally |
| Page refresh / crash mid-play | On resume, the server knows the current phase. Same recovery rule (one per module). Later phases follow the server plan (time lost is not restored) |
| Repeated interruptions | After the recovery is used: no further replays; an incident is recorded; attempt flagged "interrupted" in analytics (excluded from calibration statistics) |

## A8. Completion and submission
At the end of the review window (or on "Abgeben"), the module is submitted. Late saves follow the engine's grace window (`B1-EXAM-ENGINE-SPEC.md` §4).

## B3. Voice cast
| Rule | Value |
|---|---|
| Cast pool for Mock + Sets 01–10 | ≥ 16 distinct voices: 8 female, 8 male; ages ≈ 20–70; all native German speakers (standard German), ≥ 2 with authentic Austrian and ≥ 2 with authentic Swiss standard pronunciation |
| Per form | 9–12 distinct voices; T3 man + woman; T4 three clearly distinct voices (≥ 7 of 11 forms mixed-gender guests; otherwise strong age/timbre contrast) [balancing spec] |
| Re-use | A voice may appear in several forms, but not in the same role type twice in a form; no voice appears in more than 4 forms in the same part |
| Speaker identity | Each voice has a profile (id, gender, age band, region, timbre notes); fictional speaker names in scripts never match real people |
| Production route | **[OD-14]** (a) studio with voice actors (preferred for T3/T4 interaction realism), or (b) premium neural voices **only** if they pass human naturalness review (MOS ≥ 4.0/5, 10 native raters) and OS §23.5. Never browser TTS |
| Consent and licence | Written voice-talent release for exam use, AI-training exclusion, perpetual licence for the forms |

## B4. Performance and acoustics
- **Pronunciation:** standard German (DE), with designated AT/CH parts (≤ 1 part per form) using genuine regional standard, not caricature.
- **Style:** natural spontaneous-like delivery for T3/T4 (hesitations allowed at B1 level, no overlaps > 300 ms), announcer style for T1 announcements, guide style for T2.
- **Pauses:** natural phrase pauses; mean pause 300–700 ms; no artificial long silences inside a play; inter-turn gap 200–600 ms.
- **Room:** dry, consistent room tone (RT60 < 0.3 s). Light ambience is allowed for announcements (station/airport), ≥ 25 dB below speech, never masking keywords.
- **Telephone effect:** voicemails may use band-limiting (300–3,400 Hz) with intelligibility checked.

## B5. Technical specification
| Property | Master | Delivery |
|---|---|---|
| Format | WAV PCM 48 kHz / 24-bit, mono | **Opus in WebM** (`audio/webm;codecs=opus`) 64 kbps mono + **AAC-LC in MP4** (`audio/mp4`) 96 kbps mono fallback (Safari) |
| Loudness | Integrated **−18 LUFS ± 1** per segment (EBU R128 measurement) | Same |
| True peak | ≤ −1.0 dBTP | Same |
| Noise floor | ≤ −60 dBFS (between phrases) | – |
| Leading/trailing silence | 300 ms ± 50 ms | Same |
| Segmentation | One file per play unit (T1 each text, T2, T3, T4) + instruction files | – |
| Instructions | Spoken instruction files (neutral narrator voice, consistent across forms) | – |

## B6. Naming, manifest, storage, caching
- **Naming:** `audio/<form_id>/<part>/<segment>.<sha256-12>.<opus|m4a>` (content-addressed; immutable).
- **Manifest** (per form, server-side, part of the release):
  ```ts
  type AudioAssetMeta = { asset_id; form_id; part; segment; role:"instruction"|"stimulus";
    speakers:{speaker_id; voice_id; name_in_script; gender; age_band; region}[];
    duration_ms; speech_ms; words; rate_net_wpm; rate_gross_wpm; loudness_lufs; true_peak_dbtp;
    sample_rate; codecs:{opus:{bytes,sha256}; aac:{bytes,sha256}}; transcript_asset; alignment_coverage;
    plays: 1|2; production:{route:"studio"|"neural"; session; engineer; date}; licence_ref };
  ```
- **Storage:** private R2 `klarweg-exam-content/releases/<r>/audio/...`.
- **Delivery:** signed, attempt-bound URLs via the exam Worker (`/exam/media/:token`, Range support), TTL 5 min for preload.
- **Caching:** `Cache-Control: private, no-store` (no shared or CDN caching; the in-memory decode is the only client copy). **Never** jsDelivr, Pages or the `klarweg-audio` repo.
- **Transcripts:** stored with timestamps (forced alignment). Released only in post-submission review.

## B7. Validation (gate Q11, automated)
1. Loudness, true peak, sample rate, channel count, codec and duration are within the spec.
2. Speech rate (net, from alignment) within the part target ± 5 %.
3. Alignment coverage ≥ 98 % of transcript words. Every item anchor timestamp is inside its segment.
4. Speaker diarisation count = manifest speakers. No overlap > 300 ms.
5. Every MC option value referenced in the audio is present in the transcript where the design says so (distractor mention check).
6. Phase plan total within 36–42 min.
7. A human listening QA sign-off per form (native speaker + B1 teacher): intelligibility, naturalness, regional authenticity, no unintended cues (stress or pauses that give away the key).
