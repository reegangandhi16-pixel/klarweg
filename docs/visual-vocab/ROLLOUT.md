## Per-batch procedure
1. `pipeline.mjs plan --batch NAME --level aN` builds the queue from the data (no cost).
2. **Review** every concept and write `docs/visual-vocab/prompts/NAME.json`:
   - `text-only` where a picture would mislead: connectors, catch-all verbs,
     words whose meanings conflict, sensitive identity topics, official documents;
   - a concrete `subject` for abstract words and idioms (show the intended meaning);
   - `sameAs` to share one image across near-duplicate wordings.
3. Owner approves the budget.
4. `generate --batch NAME --max-usd N --approved-by-owner` runs sequentially
   and resumably. The ledger lives at `$VOCAB_IMG_STORE/ledger.jsonl`. It never
   pays twice for a concept and allows at most 3 attempts.
5. `sheets` → visual QA → `review.json` (`reject` → re-roll; `text-only` → drop).
6. `encode` → `apply` writes `img` with a verified writer: the data is
   re-evaluated, nothing else may change. Public files are allowlisted.
7. `npm test`, the site artifact build, then a browser check at 320, 390, tablet and desktop.
8. A PR per batch. No merge or deploy without the owner.

## Cost levers
- Per-batch review (−30 to −40 % images).
- `sameAs` for near-duplicates (up to 302 headwords).
- Gemini batch mode at 50 %, if Vertex supports it for `gemini-2.5-flash-image`.
  Verify with one free catalogue call before batch 3.
- One candidate per concept; re-roll only QA rejects.
